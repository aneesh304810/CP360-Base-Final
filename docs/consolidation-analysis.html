The finding that changes the answer

The repositories whose names promise a finished build are the ones that contain the least.

Every repo in the Env360 line — including Env360finalupdatedv8, the newest thing in the account — is a patch bundle, not a codebase. Each holds 14–19 files under a single "Add files via upload" commit. Your own manifest says so on line two:

11 impacted files + SQL. Everything else in your repo untouched.

Env360finalupdatedv8 / IMPACTED.md

Those eleven files land in ui/src/, api/app/, ingestion/ and sql/ — directories that live somewhere else. Begin the enterprise version from v8 and you inherit eleven files and no application.

The real shape of the work is one base application plus roughly twenty-four feature patches scattered across separate repositories. The migration numbers are what put them back in order.

Resolve before you build

Six items stand between the assembled repository and an enterprise foundation.

Blocker

No tests, no CI, no git history

Every one of the 105 repositories is a single upload commit. There is not one test file or pipeline anywhere in the account. For an enterprise version this is a larger gap than any missing migration — and the first thing to fix once the base is assembled.

Blocker

Migration 30 is absent

The chain jumps 29 → 31. Confirm whether it exists locally or was never written; until then the schema cannot be rebuilt from scratch on a clean database.

Fix

Renumber the duplicate 27

Two distinct schema changes share the number. Moving 27_legacy_lineage_update.sql to 30 resolves the collision and the gap in one edit.

Fix

routers_environment360 is not mounted

Absent from the router tuple in main.py, so /env/overview returns 404 and the panels silently fall back to demo data. Already documented in your own IMPACTED.md as a known open item.

Fix

Duplicated files inside patch bundles

Several bundles ship the same file at the root and under ui-src/ or api-app/ — v8 carries env_infra_ingest.py twice. Keep the path-qualified copy; the root copies are drop artifacts.

Benign

Migration 05 never existed. The skip from 04 to 06 is consistent across all 105 repositories, so it is intentional numbering, not a loss.

Keep these out

Separate products. Folding them in would dilute the base rather than extend it.

Final-Sei-Account Airflow + dbt SEI accounting demo. 67 files, its own medallion pipeline and seed data. Unrelated to the catalog.
Cpguardrails Jenkins and OPA policy framework for CI. Useful alongside CP360 as a pipeline, never inside it.
Pocsize Sizing proof-of-concept — dbt models, k8s manifests, sizing reports. Research, not product.
